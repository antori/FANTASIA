## Reviewer checklist

- Contracts provided: **C-asr** — a failed transcription is reported through `FWhisperResult` (`bSuccess` false, `ErrorMessage` set), never an exception; a failed model load fires `OnModelLoaded(false)`; a GPU backend that is absent falls back to CPU with a warning, and a CUDA runtime that fails to *resolve* is not detected at all. **C-rest-tts** — this is the project's only subclassing agreement: five virtuals (`BuildSynthesisRequest`, `ProcessResponse`, `WakeConsumer`, `CreateStreamDecoder`, `EndTurn`) plus protected buffer state. **C-elevenlabs-protocol** — every function static and stateless; the stream decoder is caller-owned and not thread-safe. **C-ace-tts** — end of turn is mandatory, not optional as in the base class.
- Contracts consumed: **C-fantasia-types** (M-tts, and M-ace by naming `FTTSData` in a public override signature), **C-build** (M-asr reads `FANTASIA_WITH_CUDA`), **C-rest-tts** and **C-elevenlabs-protocol** (M-ace, from M-tts — same owner, so the ownership hook will not catch a breaking change here; the CR discipline must).
- Invariants: audio is 16 kHz mono float PCM into `TranscribeAudioData`, and output is always mono 16 kHz — a WAV header is detected and resampled, `SampleRate` is the assumed rate for a headerless stream only. `Backend` is read at `LoadModel` time; changing it later does nothing until reload. Transcription and synthesis run off the game thread; every delegate is broadcast on the game thread. Each `TTSSynthesize` call gets its own buffer keyed by id, never shared across calls. Submission order is recorded but **not** enforced by M-tts, which has no consumer. `AudioDeviceIndex` of -1 is the OS default device. `bEnableHighPassFilter` and `bEnableNoiseGate` both default to true, so recognition never sees raw audio unless a caller turns them off. **M-asr makes no network call, ever** — that is the point of it. Pronunciation substitution is whole-word, case-insensitive and capitalisation-preserving.
- Language checks: see `references/languages/cpp.md`; here especially — the real-time rules below, no allocation in the capture or playback callback, `TArray::Reserve` before the append loops, and no lock held across a blocking call. `Category` on every `BlueprintReadWrite` property.
- Principles at risk: **P-15** — F-008's second half is here: `URESTTTSComponent::Headers` lacks the `Config` specifier and is exactly where an `xi-api-key` goes, while `URL` and `BodyTemplate` either side of it have it. **P-05** in its real-time reading: these are the modules the brief's `Real-time: yes` is about. **P-03** — `C-rest-tts` is consumed by a subclass, so a protected-member change is a contract change. **P-12** — F-016 is open: FANTASIAACE's committed binaries are the 5.7 build.
- NFRs touched: **NFR-001** (speech heard to transcript, Measure unknown), **NFR-002** (text to first audible sample, Measure unknown), **NFR-003** (audio to blendshape, Measure unknown), **NFR-004**. Three of the four have no budget; the first task that can measure one should propose it to the planner rather than leave `unknown`.
- Known weak spots: **F-009** (major) `URESTTTSComponent` buffers and records order but has no consumer — ordering, pacing, `PlaybackComplete` and a non-empty `EndTurn()` all live in M-ace, and the delegate's own doc comment describes a third behaviour that does not happen. **F-003** (major) the ten ElevenLabs properties are duplicated between `UElevenLabsTTSComponent` and `UACEElevenLabsTTSComponent`, hand-synchronised, already diverged on end-of-turn. Both are inside this one owner's paths, so both are fixable without a cross-coder request — but both change contracts. **F-016** (major) the stale ACE binaries. **F-007** (major) `WhisperCaptureComponent.cpp`, 1250 lines, the largest file in the project and completely untested. Hotspots: `RESTTTSComponent.h` and `.cpp` 15 commits each, `ElevenLabsTTSComponent` 13 and 12.
- Evidence to produce: the story's `Tests:` path run; the gate; for anything touching the capture loop or the playback consumer, a before-and-after measurement rather than an assertion that it is no slower; for M-ace, confirmation that the A2F session closes at end of turn.

## Tester plan

- Unit: the PCM16 decoder on an odd trailing byte, an empty feed, and a chunk boundary mid-sample; the ElevenLabs stream decoder on a server-sent line split across reads and on one that never completes; `WordsFromCharacters` on empty input, a single character, runs of spaces, a trailing space, and an accented glyph (the implementation flags that last one as unresolved); `ApplyPronunciations` for a key inside a longer word, which must *not* be replaced; the subtitle formatters past one hour; `ParseModelFileName` on a name that does not match the convention. Then the untested surface F-007 names: VAD segmentation at the silence threshold, the noise gate's attack and release, buffer clearing mid-capture, `StartCapture` when already capturing, and device index -1 against a machine with no input device.
- Security surface: `docs/ateam/threat-model.md` § M-asr, M-tts, M-ace — the security engineer fills it. In outline: the `Key` and `Headers` paths and where they are written (F-008); a TTS endpoint and body template taken from configuration, so a URL and a request body are both caller-controlled; audio file paths from Blueprint; and the model file path, which is read from disk at `LoadModel`.
- Stress: NFR-001 and NFR-002 have no Measure, so the first job is a baseline on the reference machine (RTX 4060, 8 GB) — microphone to transcript for a 3-second utterance on CPU and on GPU, and text to first audible sample against a live ElevenLabs endpoint. Then sustained capture for an hour, watching for buffer growth, and ten concurrent `TTSSynthesize` calls to check ordering and that nothing is dropped. Report the baselines to the planner so the NFRs can stop saying `unknown`.
- Tools: the UE automation framework. GPU paths need the CUDA stack staged, so a GPU test must skip cleanly when it is absent rather than fail.
- Paths: `FANTASIA/Source/FANTASIATests/Private/` for unit and stress. M-ace has no test module at all yet; `FANTASIAACE/Source/FANTASIAACETests/` is where one belongs, and creating it is M-dist's work (a new module needs a `.Build.cs`), so it is a cross-coder request to `build-dev`.
