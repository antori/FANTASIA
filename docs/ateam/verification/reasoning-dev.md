## Reviewer checklist

- Contracts provided: **C-prolog** — a query that cannot be parsed or run fires `QueryFailed` with the engine's message, never an exception; `nextSolution()` past the last solution fires `AllSolutionsReady` instead of `SolutionAvailable`; if the SWI-Prolog runtime DLLs are not beside the plugin binaries, initialisation fails at editor startup with a logged diagnostic and every later query fails — the project's single most common installation failure. **C-probabilistic** — duplicate variables and duplicate arcs are rejected and logged, the model left unchanged; `idFromName` on an unknown name returns negative; `getPosterior` before `makeInference()` returns empty; aGrUM exceptions are caught at the boundary, which is why exceptions are enabled in this module. **C-math** — `predict` with no model or no samples returns empty and logs; `evaluate` before `setData` returns zero.
- Contracts consumed: **C-fantasia-types** (the whole Prolog term class hierarchy lives there, in M-core, not here — so adding a term type is a cross-coder request to `core-dev` *and* a Blueprint-ABI change), **C-math** (M-probabilistic consumes M-ml's estimator), **C-build** (`WITH_AGRUM_BINDING`).
- Invariants: one Prolog engine per component on its own thread, because SWI-Prolog is not re-entrant, so queries are serialised in submission order; queries are submitted from the game thread and solutions broadcast on it; the engine never runs on the game thread. Term construction is pure and allocation-only — building a term touches no engine. `asserta` versus `assertz` is the `asFirstClause` flag. `Init()` must be called before any inference and again after the structure changes; inference is dispatched off the game thread and `InferenceReady` broadcast on it. Posteriors are keyed by variable label and sum to one. `fillCPT` takes row-major order over the node's parents. A discretised variable with `nPoints` ticks has `nPoints - 1` bins. aGrUM's static libraries link ID, then BN, then BASE, because MSVC's single-pass linker needs each to precede its dependency (ADR-0009) — and that order is `build-dev`'s file, not this one's.
- Language checks: see `references/languages/cpp.md`; here especially — no `std::` type in a public signature (F-010 is exactly that mistake), exception safety at the aGrUM boundary since this is the one module that enables them deliberately, and no Prolog term built by string concatenation when the term objects exist.
- Principles at risk: **P-06** — aGrUM is the dependency ADR-0009 governs and ADR-0015 amends; a version move is never a silent one. **P-03** — C-probabilistic's invariants name aGrUM 2.x, so the migration rewrites a contract. **P-04** — US-022's four behaviour changes move results the tests pin, so "the tests pass" is not evidence until each has a recorded verdict. **P-19** — the migration is not minor by the approved bar, which is why every CR-003 story targets 5.9.
- NFRs touched: **NFR-004**. No latency NFR names these modules, but inference is dispatched off the game thread for the same reason the real-time modules care: a synchronous Shafer-Shenoy run on a large network would stall a frame.
- Known weak spots: **F-005** (minor) `WITH_AGRUM_BINDING` is honoured by the tests and by M-demo but not by this module, which includes aGrUM headers unconditionally — so the define cannot disable the binding and a non-Win64 build fails to compile rather than building without it. Folded into US-022. **F-010** (minor) `Linspace` is a free function returning `std::vector<float>` from a public header: not Blueprint-reachable, and a standard-library type crossing the boundary of a prebuilt plugin. Hotspots: `BayesianNetwork.h` and `.cpp` 11 commits each, `SWIPrologComponent.cpp` 11, `InfluenceDiag` 8 and 8, `SWIPrologThread.cpp` 7. Well covered where it is covered — 16 aGrUM tests, 7 Prolog term tests, 4 Linspace, 3 SVM — and not covered at all for the component, the thread, or the engine lifecycle.
- Evidence to produce: the story's `Tests:` path run; the gate; for US-022, the aGrUM version and the exact library target names **read off the build**, never from a changelog, plus one recorded verdict per behaviour change.

## Tester plan

- Unit: the Prolog term renderers for every type including `USWIPrologHeadToTail` and `USWIPrologCut`, which the suite does not reach; a malformed goal; `nextSolution()` called past the end; `SWIPLconsultString` with a syntax error. For the probabilistic side: a CPT of the wrong length, an arc that would create a cycle, erasing a node that has arcs, `getMEU` on a diagram with no valid decision order, and `decisionOrderExists()` false. For M-ml: a ragged training set, which libsvm does not check and which silently produces a wrong model.
- Security surface: `docs/ateam/threat-model.md` § M-prolog, M-probabilistic, M-ml — the security engineer fills it. In outline, the sharpest item in the project: **`SWIPLqueryString` and `SWIPLconsultString` take a string and run it as Prolog**, so anything that reaches them from a model, a file or a user is code execution inside the engine. Also `openPrologFile` taking a path from Blueprint, and `setBN`/`writeBIF`/`writeBIFXML` reading and writing files by caller-supplied path.
- Stress: a Bayesian network large enough that exact inference takes measurable time, confirming the game thread is not blocked and reporting the time as a baseline; a Prolog query that backtracks heavily, checking the thread stays responsive and memory is bounded; after US-022, the same two runs against 3.x so the migration's performance effect is a number rather than an impression.
- Tools: the UE automation framework. The aGrUM tests are already guarded by `WITH_AGRUM_BINDING`, which is the right pattern and the one F-005 says the module itself does not follow.
- Paths: `FANTASIA/Source/FANTASIATests/Private/` for unit and stress; the security cases go to `FANTASIA/Source/FANTASIATests/Private/Security/`, which is the security engineer's.
